# 확률 실험 시뮬레이터 · 확률 실험실

내가 직접 **도구와 경우를 정해서** 확률 실험을 만들고, 던져 보며 도수·상대도수를 살펴보는 프로그램이에요.
만든 실험은 우리 학교에 올릴 수 있고, 친구들은 **결과만 보고** "각 경우가 일어날 가능성이 같을까?"를 판단해요.

## 파일

| 파일 | 하는 일 |
|---|---|
| `probability/sim/index.html` | 화면 전체 (만들기·실험하기·친구 실험 판정하기). 이 파일만 열어도 만들기·실험하기는 돼요. |
| `api/sim.js` | 올리기·목록·던지기·판정·지우기를 처리하는 Vercel 서버 함수 |
| `api/_simlib.js` | 값 검사와 난수 던지기 도구 |

학년도·학교 목록(`/api/config`), 저장소(Upstash Redis), 이름 검사(`api/_names.js`), 내 정보(`me-sync.js`, `lab-bar.js`)는 강 건너기·동전 실험실과 **같은 것**을 그대로 써요. 새로 넣을 환경 변수는 없어요.

## 사용 흐름

1. **처음 화면**: "각 경우가 발생할 가능성이 동등한 경우" / "동등하지 않은 경우" 중에서 골라요.
2. **도구 만들기**: 도구 이름과 경우를 **직접 써요.** 입력칸은 모두 빈칸이고, 흐린 글씨(placeholder)로 예시만 보여 줘요. 경우는 2~30개까지 추가·삭제할 수 있어요.
   - 동등한 경우: 이름만 써요. 모든 경우의 확률이 똑같이 설정돼요. (예시: 정사면체 주사위 1·2·3·4, 빈칸 4개로 시작)
   - 동등하지 않은 경우: 경우마다 **상대도수**를 써요. (소수 `0.25` 또는 분수 `1/4`) 합이 1이 아니면 실험을 시작할 수 없고, "마지막 값 채우기" 버튼이 도와줘요. (예시는 ‘예시 보기’ 버튼으로 고를 수 있어요: 압정 0.4 / 0.6, 윷 도 0.25 · 개 0.375 · 걸 0.25 · 윷 0.0625 · 모 0.0625. 예시를 고르면 입력칸의 흐린 글씨만 바뀌고, 이미 쓴 내용은 그대로예요)
3. **확률 실험하기** (두 가지)
   - **n번 던지기** (n은 1~10,000): 결과 상자(스크롤) · 도수와 상대도수 표 · 도수 막대그래프 · 던진 횟수에 따른 상대도수 꺾은선그래프 (세로축은 처음에 **0~1 전체**, ‘자동 확대’로 바꿀 수 있어요)
   - **n번씩 k회 반복하기** (n 1~1,000, k 1~1,000, n×k ≤ 200,000): 경우를 하나 고르고, 한 회(n번)에 그 경우가 나온 도수를 k회 모아 **도수의 분포**(히스토그램·표)로 보여 줘요. 가로축은 나올 수 있는 모든 값 0~n이에요. (n이 100을 넘으면 같은 폭으로 묶어요)
   - 만든 사람은 "내가 정한 확률 보기"를 켜서 표·그래프에 설정한 확률(점선)을 겹쳐 볼 수 있어요.
4. **우리 학교에 올리기**: 내 학교·학년도에 올라가요. 한 사람이 10개까지 올려 둘 수 있어요.
5. **우리 학교 실험 판정하기**: 같은 학교 친구들이 올린 실험 목록에서 골라 던져 보고, "같다 / 같지 않다"를 **한 번만** 제출해요.
   - 학생은 **던지는 횟수를 정할 수 없어요.** ▶ 시작을 누르면 서버가 1초마다 (속도는 느리게 1 · 보통 5 · 빠르게 20 · 아주 빠르게 100번) 던져서 결과·도수·그래프가 계속 쌓이고, 확신이 들 때 ⏸ 멈춤 → 판단해요. 한 실험에서 최대 20,000번까지예요. 결과 상자는 최근 400번만 보여 주고, 도수와 그래프에는 모두 들어가요.
   - **던진 횟수는 서버가 서명해서 이어 줘요.** 서버가 `{누적 횟수, 서명(tok)}`을 돌려주고 학생 화면이 다음 요청과 판단 제출 때 그대로 보내요. 서명이 맞지 않으면 인정하지 않아요. Redis에 횟수를 쓰지 않아서 요청량이 적어요. (서명 비밀값은 `RD_ADMIN_KEY`에서 만들어요. 이 값을 바꾸면 던지는 중이던 학생은 실험을 다시 열어야 해요.) 판단을 제출하면 `선택 · 던진 횟수 · 옳은지`가 기록돼요. 던지지 않고는 제출할 수 없어요.
   - 제출하면 **바로 정답(같다/같지 않다)과 맞았는지**, 내가 던진 횟수, 친구들의 누적 판단이 보여요. 0.48과 0.52처럼 거의 비슷하면 구분이 사실상 어렵다는 안내가 함께 나와요. 순위는 매기지 않아요.
   - 내가 올린 실험은 판정할 수 없고, 목록에서 열면 **집계 보기**가 나와요. (관리자도 같아요) 전체 / 옳게 판단한 학생 / 틀리게 판단한 학생을 골라 인원, 정답률, 평균·중앙값·최소~최대 던진 횟수, 던진 횟수의 분포(히스토그램)를 볼 수 있어요. 누가 판단했는지는 알 수 없어요.
   - 목록에서 "링크 복사"를 누르면 `/probability/sim/?e=실험번호` 주소를 복사해요. 이 주소로 들어오면 바로 그 실험이 열려요.
   - 만든 사람은 도구를 만드는 화면(올리기 전후)에서 지금처럼 횟수를 입력해 던지고 반복할 수 있어요.

## 경우가 많을 때 (9~30개)
- 경우마다 다른 색은 **8가지까지만** 안전하게 구분돼서, 9개 이상이면 그래프·칩을 한 가지 색(보라)으로 그려요. 경우는 이름·표의 순서로 구분해요.
- 막대그래프의 가로 눈금은 이름이 들어갈 자리가 없으면 번호(표의 순서)로 바뀌어요.
- 꺾은선그래프에는 ‘강조할 경우’ 선택이 생겨서, 고른 경우의 선만 분홍색으로 굵게 보여 줘요. (경우가 많으면 세로축 0~1에서는 선들이 아래쪽에 몰리니 ‘자동 확대’를 써 보세요)

## 우리 학교 실험 목록의 순서
- 관리자가 ⭐ 추천한 실험이 맨 위 (여러 개면 최근에 추천한 것이 위)
- 그다음은 판정에 참여한 친구가 많은 순, 참여 수가 같으면 최근에 올린 순
- 관리자 보기(‘지우기’와 ‘판단 초기화’도 여기서): 목록 맨 아래 ‘관리자’ 버튼 → 관리자 암호(`RD_ADMIN_KEY`) 입력 → 각 실험에 ‘추천하기/추천 해제’와 ‘지우기’ 버튼이 나타나요. 이 탭에서만 유지돼요(탭을 닫으면 꺼짐).

## 정답(확률)은 서버에만 있어요
올린 실험의 확률은 서버에만 저장되고, 목록·실험 화면으로는 **내보내지 않아요.** 친구들의 던지기도 서버가 대신 던져서 결과만 돌려줘요. 판단을 제출한 뒤에만 정답(같다/같지 않다)을 알려 줘요.
그래서 브라우저 개발자 도구로도 정답을 알 수 없어요. (만든 사람 자신의 컴퓨터에서 하는 실험은 서버 없이 브라우저에서 던져요.)

## API (`/api/sim`, 모두 POST + JSON, 본문의 `act`로 구분)

| act | 보내는 값 | 돌려주는 값 |
|---|---|---|
| `publish` | year, school, uid, nick, tool, cases[], w[] | `{ id }` |
| `list` | year, school, uid | `{ items }` (추천 → 참여 많은 순 → 최근 순, 50개까지) |
| `get` | id, uid | `{ item }` |
| `step` | id, uid, n(1~200), total, tok | `{ r, total, tok }` — 경우 번호를 한 글자씩 이은 문자열, 서버가 서명한 누적 횟수 |
| `vote` | id, uid, choice(`e`=같다 · `n`=같지 않다), total, tok | `{ tally, my, eq, ok, n }` — 정답·맞았는지·던진 횟수 |
| `stats` | id, uid (만든 사람) 또는 헤더 `x-admin-key` | `{ eq, tally, items:[{ok,n}], legacy }` |
| `remove` | id, uid (관리자는 헤더 `x-admin-key`) | `{ ok }` |
| `feature` | id, on(true/false) + 헤더 `x-admin-key` | `{ ok, feat }` |
| `resetvotes` | id + 헤더 `x-admin-key` | `{ ok }` — 판단·집계만 0으로 (실험은 남아요) |
| `adminping` | 헤더 `x-admin-key` | `{ ok }` |

- 저장 위치(Redis): `sm:e:<id>`(실험 본문) · `sm:idx:<학년도>:<학교>`(목록) · `sm:v:<id>`(집계) · `sm:vu:<id>`(누가 어떻게 판정했는지: 선택·던진 횟수·옳은지) · `sm:own:<uid>`(내가 올린 것). 약 13개월 뒤 저절로 지워져요.
- 학교·학년도마다 최대 100개 (넘으면 오래된 것부터 지워요).
- 도구·경우 이름과 별명은 서버가 금지어를 검사해요. 같은 IP에서 던지기는 1분에 6,000번, 올리기·판정은 60번까지예요.

## 잘못 올라온 실험 지우기 (관리자)
`RD_ADMIN_KEY`(강 건너기와 같은 암호)로 지울 수 있어요. 실험 번호는 목록 화면의 "링크 복사"로 나오는 주소 끝에 있어요.

```
curl -X POST "https://mtryu-lab.vercel.app/api/sim" -H "Content-Type: application/json" -H "x-admin-key: 비밀문구" -d '{"act":"remove","id":"실험번호"}'
```

## 서버가 확인하는 것, 못 하는 것
- 도구·경우 이름(금지어·길이·중복), 경우 수, 확률 값, 학년도·학교(등록된 것만)는 서버가 확인해요.
- 판정은 기기별 익명 번호(uid)로 한 번만 받아요. 하지만 같은 사람이 브라우저 저장 데이터를 지우고 새 정보로 들어오면 다시 판정할 수 있어요. (로그인이 붙으면 막을 수 있어요)
- 던진 결과는 서버의 암호용 난수로 만들어져요.

## 고칠 때 참고
- 경우 최대 개수(30개)는 `index.html`의 `MAX_CASES`와 `api/_simlib.js`의 `MAX_CASES`가 서로 같아야 해요. 색은 8가지(`SC`, `.k0~.k7`, `PAL`)까지만 쓰고, 그 이상은 한 가지 색으로 그려요. 던진 결과는 경우 번호를 한 글자(번호+48의 문자)로 서버에서 받아요.
- 던지기 상한은 `index.html`의 `MAX_ROLL`·`MAX_REP_*`와 `api/_simlib.js`의 같은 이름 값이 서로 같아야 해요.
